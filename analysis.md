Q1: Micro-Architectural Root Cause of False Sharing As the experiment results demonstrate, Variant 1 (Naive array) resulted in an average execution time of 0.435 seconds, whereas the Reduction method completed in 0.377 seconds. This performance degradation occurs because multiple OpenMP threads share the same 128-byte L1 cache line. According to the system's MESI/MOESI cache protocol, when one thread updates its respective variable, the data for other cores residing on that same cache line is marked as invalidated. This generates constant bus invalidation traffic on the system bus, wasting computational resources and severely slowing down the program.
Q2: Hyperthreading (SMT) Saturation & Physical Core Ceilings
As the thread count $k$ increases, linear speedup eventually stops. In the provided data, the execution time for $k=4$ was 0.589 seconds, while for $k=8$ it was 0.383 seconds, indicating that performance did not double. My hw_info.txt shows that hw.physicalcpu and hw.logicalcpu are both equal to 8, meaning the Apple M1 has no SMT/Hyperthreading — physical and logical core counts are identical. Therefore k=8 did not exceed the physical core count; it reached it exactly. The sub-linear scaling from k=4 to k=8 is instead explained by memory bandwidth saturation, as all 8 cores contend for the same shared memory controller, combined with workload imbalance caused by the M1's heterogeneous core speeds (4 Performance cores run faster than the 4 Efficiency cores), so static scheduling forces faster cores to idle at the barrier waiting for slower ones.
Q3: Empirical vs. Theoretical Amdahl Discrepancy The empirical speedup at $k=2$ threads is $S_{emp}(2) = 2.109 / 1.116 \approx 1.889$. Using Amdahl's formula $p = 2 \times [1 - (1/S_{emp}(2))]$, the derived parallel fraction $p$ is approximately $0.941$ (or 94.1%). As the thread count reaches $k=8$, the theoretical curve ($S_{theo}(8) \approx 5.67$) begins to diverge from the empirical result ($S_{emp}(8) \approx 5.50$). This discrepancy occurs because Amdahl's Law assumes a perfect scenario with zero communication latency and perfect memory bandwidth scaling. Two real physical factors omitted by Amdahl's equation that cause this divergence are sequential overhead (such as thread spawning and waiting at synchronization barriers) and memory bandwidth saturation.
